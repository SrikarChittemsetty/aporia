Why this is harder than it sounds

Ordinary semantic search finds passages about a topic. It cannot tell a defence of free will from an attack on it, because the two say almost exactly the same words about almost exactly the same things — they sit right next to each other in the mathematics.

So Aporia does the retrieval first and then asks a language model one question per passage: relative to this specific claim, is this passage arguing for it, against it, or reframing the question? Answers are cached per claim, so a given claim costs one model call ever. That second layer is the whole project — a search engine that returns a debate rather than a reading list.

How it was built

The search index was written from scratch

Rather than calling a vector-database library, the HNSW nearest-neighbour index was implemented in NumPy directly from the 2016 Malkov–Yashunin paper — hierarchical proximity graphs, geometric level assignment, beam search, heuristic neighbour selection. It serves this demo. It is not a side experiment.

It is measured against the library it replaces

Behind the same interface as hnswlib, the C++ implementation most people reach for, so the two can be swapped with one config line and benchmarked head to head.

The corpus was audited, not just downloaded

A data check caught 492 chunks of a Victorian translator’s commentary being attributed to Plato, and a heading-detection bug that was turning dialogue replies like “I do.” into citation paths. Both are fixed, both have regression tests, and the corpus is now 3,723 passages of authorial text.

The classifier is evaluated, not trusted

83 hand-labelled stance judgements form a gold set with an agreement harness, and ten hand-written claims check that retrieval surfaces the philosopher who actually holds the position — currently 9 of 10. Ten tests run in CI on every push.

About this page. It is a frozen snapshot of the real system, so it can run with no install and no API key. The passages and their ranking are genuine output from the pipeline: the same bge-small embeddings through the same from-scratch HNSW index that serves the live app. The stance labels were produced by Claude from the pipeline’s own classification prompt and written to the same cache the live app reads, which is exactly what happens when you run it yourself with a key set. The twelve claims are curated; the live app takes anything you type.
